# AskBase Local 0.3.0 多模态验收协议

协议：MM03-P1。冻结日期：2026-10-09。范围：Apple Silicon 本机工程验收。

## 问题与完成条件

EmbeddingGemma 2 的图像、音频、视频编码器接入本地知识库。用户选中的原文件保存在本机；语义检索能返回图片帧／页或音视频时间段，并在原生窗口中预览、播放。视频记录原文件的采样时间点。图片和视频中实际识别出的文字可以进入文字 RAG；未转写音频及无可读文字的媒体不得伪装成原文来源。

保留 0.2.0 的文本编码路径、编码签名和已保存资料。现有文本向量不因为增加媒体接口而要求重建。媒体另外保存编码签名与客户端预处理版本；不兼容时明确要求重建，不能混用。

## 固定配置与资源预算

- 模型：`google/embeddinggemma-2@914f7f89142e33e77833254d9c9b90c3cef7303b`。
- 本机：Apple Silicon，使用已下载的模型、现有 MLX 环境和已有本地回答模型。
- 文档和查询均为 768 维、L2 归一化，区分 query / document。
- 一次处理一段媒体；音视频每段不超过 10 秒，视频每段 1–8 帧。
- 专家服务检查预算：不超过 12 次媒体编码、6 次文本对齐检查。
- 主代理集成与界面检查预算：不超过 48 次媒体编码、40 次文本请求、2 次本地回答生成。失败与重试计入；追加前记录原因与实际使用量。
- 不并发运行两组模型检查，不下载额外 ASR 或视觉生成模型，不调用付费远程推理。
- 所有验收使用合成文件和新建临时资料库；不扫描、修改或拿真实用户资料作测试集。

## 必须检查

1. **兼容性**：旧 JSON / SQLite 文本记录仍可读取；原 `encoder.py` 文件哈希和文本服务签名不变。完整多模态模型的文本编码与原文本编码器对齐，并记录余弦和误差容差。
2. **原生输入**：真实图片字节、音频采样和视频帧进入相应编码器；媒体文件名或占位说明不能作为替代输入。包括无扩展名文件。
3. **时序覆盖**：音频和视频包含超过一段的合成文件以及尾段；时间范围从零连续覆盖到结束，帧时间位于片段内。视频有声、无声情况分别处理。
4. **索引与恢复**：完整媒体提交为 ready；部分失败、取消和中途删除不会留下半套可用向量。失败重建保留旧索引。
5. **检索**：文字检索媒体、媒体检索文字/媒体；查询文件不自动入库；知识库隔离；编码版本不一致时拒绝查询。
6. **可追溯性**：图片帧／页位置、音视频起止时间、视频采样时间点、是否包含音轨及 OCR 来源持久化并在搜索结果中保留。删除和重建撤销过期来源。
7. **问答证据**：只有文本原文或实际 OCR 可以发送给现有文字回答模型。媒体无可读文字时不调用生成器、不创建伪造转写；有文字的来源不被纯媒体检索结果挤出。
8. **界面**：导入入口、用媒体搜索、图片预览、音视频播放器及定位入口可用；播放不自动开始，切换/关闭时释放播放器。设置显示服务实际能力。
9. **边界**：损坏媒体、错误帧数、非法时间、任意路径/URL 请求、非本机地址、不兼容服务、无效向量等返回明确错误。服务请求上限仅用于单片段资源保护，不是原文件大小上限。
10. **发布**：离线测试、隔离真实模型集成、原生构建与签名、开源许可随包；安装包和运行时版本可核实且可以回退。

## 判定与证据边界

任一涉及数据丢失、伪造来源、文本向量不兼容、遗漏片段、错误时间位置或模型调用失败的问题均阻止交付。工程检查须记录实际通过数、失败原因和重跑情况；不把初次失败隐去。

有限合成样本只能证明接口、索引和已覆盖的检索流程。少量相关性命中不构成中文语音、复杂视频或真实资料库的检索质量基准。图像抽帧检查、播放器技术检查、连续观看/听音和用户验收分别记录；未完成的项明确标注。没有真实场景覆盖与验收，不标 E4。

OCR 可能有误；音频嵌入不输出转写，视频采用抽帧，不覆盖每个瞬间。扫描 PDF 仍沿用原有文字提取路径，暂不自动对每页做 OCR。

2026-10-09 术语澄清：视频 `frameTimes` 是原片时间线上的采样请求位置，不宣称为编码帧 PTS；静止画面允许重复取到同一帧。该澄清不改变分段连续覆盖、片段内采样、来源追溯或验收阈值。
