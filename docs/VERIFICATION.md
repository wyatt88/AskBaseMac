## 实际模型集成

执行：

```sh
swift run askbase smoke --model gemma4:31b-mlx
```

入口会自行创建临时目录，写入三份明确标记的虚构资料，结束时清理整个临时库。最终记录为 [model-smoke.json](verification/model-smoke.json)。

问题为“北辰计划的审核截止日期是哪天？”。返回：

> 北辰计划的文档审核截止日为 10 月 18 日 [1]。

记录中的耗时来自一次已预热、小资料量的工程检查，受模型加载、缓存及当前机器状态影响；不是吞吐基准、冷启动承诺或真实知识库质量成绩。

## 原生窗口与视觉核查

使用 Debug 构建的 `AppSmokeVerifier`，显式指定独立 `--library-path`。它调用与按钮相同的原生 AppState 操作入口，等待实际解析、向量服务及回答服务，再用 AppKit 保存本应用自身窗口内容。它不读取其他应用画面，不需要辅助功能或录屏权限。

实际结果见 [ui-verification.json](verification/ui-verification.json)。问题为“北辰计划的审核截止日是哪天，由谁负责？”，实际返回截止日期和林舟，并保存编号来源。主代理查看了实际窗口图片：

检查发现并修复了首次空库的布局问题：原生分栏按过窄内容的最小宽度推算出过高的内容高度，导致标题和侧栏被裁掉。为详情列和空状态设置合理的最小宽度后，分栏保持在窗口范围内；验收器对实际分栏边界增加了检查。另修正了重新索引菜单拉满标题栏的宽度，以及把全部检索候选误称为“引用来源”的文案。

窗口图片来自 Debug 版的实际内容区域，不包含系统标题栏；不是设计稿，也不是鼠标／键盘端到端自动化。发布版不含调试验收入口。文件选择面板、拖放、菜单快捷键、导出面板和长期使用尚未做完整人工覆盖。
