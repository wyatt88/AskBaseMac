# 0.3.0 多模态更新与验收

日期：2026-10-09，Asia/Shanghai。协议：[MM03-P1](MULTIMODAL-PROTOCOL-0.3.0.md)。

本版把 EmbeddingGemma 2 的原生图片、音频、视频编码接入 AskBase Local。原文件保存在本机，使用同一个 768 维向量空间；可用文字描述或媒体文件检索，结果保留图片帧／页与音视频时间范围。

## 已交付能力

| 输入 | 索引与使用方式 | 边界 |
| --- | --- | --- |
| 图片 | ImageIO 按内容解码，校正方向，处理每个帧／页；原生视觉向量、图片查询、原图预览 | 本机尝试 OCR，并标注为画面文字；不是自动图片描述 |
| 音频／录音 | AVFoundation 解码为 16 kHz 单声道 PCM16；连续分段索引、音频文件查询、定位播放 | 每段 20 毫秒至 10 秒；没有语音转写或麦克风录音 |
| 视频 | 连续分段，每段 1–8 帧，有音轨时一同编码；视频查询、原片时间定位 | 均匀抽帧可能漏掉短暂画面；采样位置不等同于编码帧 PTS |
| 文本与办公文档 | 保留原有解析、语义检索和带引用问答 | 本版不自动对扫描 PDF 逐页 OCR |

不设原文件大小、数量或总时长配额。长媒体逐段处理，完整覆盖尾段；单段请求上限用于控制模型内存。格式或编码不受系统支持时返回具体错误。整个音频不足 20 毫秒时明确拒绝；长文件不足 20 毫秒的尾段通过调整前一段边界保留。

在“资料库”导入媒体；在“语义搜索”输入描述，或点击“用媒体搜索…”。查询文件不会自动入库。点击来源可查看原图、选择图片帧／页，或定位播放音视频。媒体不自动播放；切换、关闭、删除或切库时释放播放器。

问答只使用真实原文或实际识别出的 OCR。没有文字的媒体仍可检索和播放，但媒体名称、占位说明不能作为转写或事实依据。问答在截取 top-K 之前筛除这些无文字来源，避免挤出真正的文字证据。

- 已升级本机 `~/Library/Application Support/AskBase/EmbeddingGemma2`；`127.0.0.1:8871/health` 确认四种模态，源码与运行文件一致。[运行时记录](verification/runtime-0.3.0.json)。
- 应用版本 **0.3.0，build 4**；安装包和签名校验见 [发布产物记录](verification/release-artifact-0.3.0.json)。

首次安装及其他机器升级仍使用 `python3 scripts/setup_embedding.py`。只报告文本能力的旧服务需要升级；新安装入口不会把可连通的旧文本服务误报为媒体已就绪，也不会停止归属不明的端口服务。

完整媒体提交后才变成可检索；失败重建保留旧索引。取消、删除或切库不会让迟到结果重新出现。被删除的长媒体停止后续分段处理。重建和删除会撤销过期来源。

本次服务工作项使用 10 次媒体编码、6 组文本对齐；主代理媒体整合 17 次媒体编码，原生窗口 4 次媒体编码。本地回答生成 2 次。全部在 MM03-P1 预算内，没有下载额外模型或调用付费远程推理。
