# 0.3.1 云盘文件导入修复

日期：2026-10-09，Asia/Shanghai。负责人：主代理；独立审阅：魏慎言岗位代理。

## 问题与原因

旧版可能对 iCloud Drive、OneDrive 等同步目录中的文件报“读取期间文件发生变化”。原导入器直接打开源文件，并要求读取前后的大小、`mtime`、`ctime` 全部相同。

`ctime` 是文件状态变化时间，扩展属性、标签及云盘维护操作也会改变它，不能直接视为正文被编辑。在本机合成文件上，读取期间写入扩展属性后，内容 SHA-256、大小和 `mtime` 均未改变，而 `ctime` 改变；旧判定规则会拒绝该文件。见[机制核验](verification/cloud-metadata-mechanism-0.3.1.json)。这证明存在误判路径，不证明每一例用户错误都由同一原因造成。

## 修复

- 通过 `NSFileCoordinator` 协调内容读取，等待 iCloud／File Provider 准备可读内容；使用系统实际交付的 URL。`withoutChanges` 表示不要求其他应用保存尚未保存的编辑，读取范围仍是文件内容。
- 协调访问期间流式复制到私有本地暂存文件。快照完成后即释放源文件，再从快照解析、计算索引并保存资料副本。
- 时间属性发生变化时，重新读取并核对完整 SHA-256；属性变化但内容相同、复核过程稳定时可以通过。内容不同、大小变化、源路径被替换或复核期间继续变化等情况会丢弃本次快照，重新协调读取。
- 最多尝试三次，重试间隔为 200／400 毫秒，避免连续追逐仍在写入的文件。持续变化时明确提示等待同步完成；每次失败都清理暂存文件。
- 应用的导入及媒体查询在后台准备快照；取消操作传递给等待中的系统协调器和读取循环。保留普通文件检查、符号链接保护及完整副本与索引一致性。

不会重新加入原文件大小、数量或时长配额。本次不改变数据库结构、模型、向量签名或媒体处理配方，已有成功索引无需重建。

复核期间持续变化的元数据仍可能消耗重试预算并保守失败；已进入内核的阻塞读取不保证立即中断。此次修复不承诺任意第三方云盘状态下都能导入。

## 使用

更新后重新导入此前失败的文件即可，已成功的资料不需要重新导入。如果云盘客户端无法提供内容，在 Finder 中右键选择 iCloud 的“立即下载”或 OneDrive 的“始终保留在此设备上”，等下载完成后再导入。云盘文件的下载由用户安装的云盘客户端完成；本地模型和应用不会为此增加云端推理。

## 方法依据

已阅读本机 Apple SDK 的 `Foundation/NSFileCoordinator.h`：内容协调读取与仅元数据读取的区别、`withoutChanges` 语义、访问期间使用传入 URL，以及可跨线程调用 `cancel()` 的约定。公开入口：[NSFileCoordinator](https://developer.apple.com/documentation/foundation/nsfilecoordinator)。

方法依据为 E2／支持；测试为本地工程检查，不标作论文复现或 E4 云盘场景验收。
